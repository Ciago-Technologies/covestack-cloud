## 1. Scope and how to use it

This plan covers **existing files only**. A row can retain behavior, change an existing file, add assertions inside an existing test, or regenerate existing outputs after agreement. It does not invent filenames for missing applications, controllers, repositories, VM/RustFS drivers, CLI modules or migrations. Those components do not already exist; changing the files below alone cannot implement the full product.

Source is the current behavior; the [product SRS](docs/product/CoveStack-Product-SRS.md), [catalogue](docs/product/CoveStack-Product-Architecture-and-Service-Catalogue.md), [HLD/LLD](docs/platform/architecture.md) and [decisions](docs/platform/decisions.md) define target requirements. VM Instance is real guest-kernel compute; App Container is distinct; RustFS is preferred **Planned** object storage. Java owns bucket/policy/credential reconciliation, operator owns the process/volumes, alternative providers remain possible. Apache-2.0 is adopted for CoveStack-owned material, not dependencies.

No row is evidence of implementation completion, approval to change a contract, or a command to rewrite every file. **Retain means keep unless new evidence justifies a change.** Conditional changes wait for the stated decision and consumers. Test assertions are required future evidence, not tests run by this documentation task. GitHub issues hold live task status; owners link the relevant rows rather than maintain guessed percentages here.
